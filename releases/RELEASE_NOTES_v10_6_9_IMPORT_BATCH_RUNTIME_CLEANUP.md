# v10.6.9 — Import/Batch runtime cleanup

Maintenance-focused hotfix. No new AI generation features were added.

## Why

During long Import Material / Batch sessions Windows may increase `C:\pagefile.sys` when the app creates memory pressure. This can look like disk space disappearing until a reboot. The app should release its own runtime references more aggressively and make cleanup visible.

## Changes

- Added a global **Clean runtime** button in the top settings bar.
- Added safe runtime cleanup helper using `gc.collect()`.
- Added best-effort diagnostics shown after manual cleanup:
  - approximate free space on the current drive,
  - `%TEMP%` size,
  - `.import_cache` size,
  - `.audio_cache` size,
  - Windows pagefile current/peak usage when available.
- Added safe app shutdown handler via `WM_DELETE_WINDOW`:
  - stops/pause-flags background Batch/Audio loops,
  - cancels the recording timer if active,
  - clears app-owned heavy references,
  - runs garbage collection before closing Tk.
- Improved cleanup after:
  - Clear Batch,
  - Clear Import Material,
  - Clear candidate drafts,
  - sending OCR candidates to Batch,
  - clearing/sending Conversation staged suggestions.
- Clear Import Material now removes app-created cached screenshot/file sources from `.import_cache` when they were generated by the current import flow.

## Notes

This does **not** delete or modify `C:\pagefile.sys`. Windows owns that file. The fix reduces app-side memory pressure and gives a manual cleanup button plus diagnostics so pagefile growth can be observed instead of guessed.
